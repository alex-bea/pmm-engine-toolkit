# Setup and adopter mapping

Resolve an explicit adopter-owned data root. Do not write to the installed skill, plugin
cache, a home-directory default, or an inferred shared location.

Initialization creates a fictional offline market plus `mapping.json`. Before live use, the
adopter must map and review:

- organization and product names;
- market boundaries, competitors, and aliases;
- communication channels and user identities;
- repository organizations, projects, and authority rules;
- company systems and explicit local-file roots;
- existing intelligence data, registries, reports, and retention rules;
- optional consented stakeholder lenses;
- connector permissions and required/optional source status;
- evidence reviewers and state-change approvers; and
- output owners and destinations.

Unmapped organization fields remain visible. They block only operations that depend on
them. The fictional market is a method demonstration, not a live default.

The foundation package implements synthetic and local-file adapters. Web and repository-
hosting integrations belong to later adapters using the same evidence contract. Optional
communication integration must remain disabled until an adopter supplies its own mapping
and least-privilege connection.
