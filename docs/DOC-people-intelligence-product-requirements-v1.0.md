# People Intelligence Public Product Requirements

## Purpose

Define the public, consent-first stakeholder-briefing skill. This document is a draft candidate specification and does not approve a release or establish authority to process personal information.

## Requirements

- **PI-REQ-001:** The package provides standalone, relational, and delta stakeholder-brief modes using only package-local resources and adopter-authorized evidence.
- **PI-REQ-002:** The workflow requires a stated professional purpose, intended audience, subject resolution, and evidence authority before analysis.
- **PI-REQ-003:** The workflow preserves a default 14-day window, directional evidence distinction, bounded context selection, and thin-evidence confirmation.
- **PI-REQ-004:** Source maps, evidence corpora, prior briefs, retention decisions, and output locations remain adopter-owned and outside the installed package.
- **PI-REQ-005:** Material claims use evidence labels, source and date citations, contradictory-evidence disclosure, and two independent observations for a recurring professional pattern.
- **PI-REQ-006:** Long-form-note, delta, and relational branches require explicit authorized inputs and omit safely when absent.
- **PI-REQ-007:** The public brief and writing-preparation templates preserve detailed work, relationship, preference, capacity, uncertainty, correction, and conditional-section structures.
- **PI-REQ-008:** The workflow stops for ambiguous identity or absent authority, requests confirmation for thin evidence, and explains limitation when optional input fails.
- **PI-REQ-009:** The package is agent-neutral, directly installable, documented, tested, and accurately represented in the public catalog.
- **PI-REQ-010:** The package excludes sensitive profiling, account scraping, external mutation, automatic persistence, private identifiers, and voice imitation.
- **PI-REQ-011:** One complete fictional scenario independently supports every template and conditional branch using reserved `.invalid` URLs.
- **PI-REQ-012:** Release preparation includes focused and full tests, document and link checks, private-term scanning, IP inventory regeneration, and a manifest-bounded diff review.
