  adopter-owned state locations only.
- Completed fixtures use the already-public fictional Acorn Studio identity, synthetic
  temporary paths, invented digests, an invented revision, and an `.invalid` contact where
  contact data appears.
- No private absolute path, worktree, remote, account, channel, registry record, approval,
  output, or secret appears in the candidate.
- No private-to-fictional substitution or alias map exists in the public repository.
- Source and destination tables name authorization mechanisms without credential values.
- The setup test forbids network calls, publishing, notifications, scheduling, production
  mutation, approval creation, plugin installation, hook activation, and CI mutation.

## State and routing review

The package uses the `local-persistence` profile. A completed configuration and compact YAML
receipt live at stable adopter-owned paths outside the installed package unless an existing
compatible canonical convention governs their location. A matching `ready` receipt routes
normal work to the sole RUN without loading setup detail. Explicit setup and `missing`,
`stale`, or `blocked` readiness route to the setup contract.

The receipt binds package revision and digest, setup-contract version, configuration path
and digest, checks, limitations, scope, and normal entrypoint. A material bound-input change
makes it stale. Dates are evidence only and do not create time-based readiness. The existing
Markdown receipt remains optional detailed evidence and cannot substitute for YAML state.

## Fictional test review

The smoke test copies the complete package into a new temporary root, creates only synthetic
Acorn Studio inputs and declared outputs, adds completed fictional setup state outside the
package, checks local links and required keys, and confirms the copied package is unchanged.
It makes no external request and writes no production state.

Conditional reference loading is instruction-only: deterministic tests verify routing text,
file shape, and isolated filesystem effects, not which file an AI model actually read. The
fictional ready receipt proves schema coherence, not a historical real installation.

## Residual risk

Automated scanning cannot prove independently conceived prose or prevent a capable agent
from ignoring model-readable routing. Repository-local documents do not create a
non-bypassable security boundary. Stronger validation, runtime, capability, or external-
authority layers require separate selection, administration, and evidence.

The skill may inspect confidential repositories selected by an adopter. Users remain
responsible for scoping access, protecting adopter-owned state, reviewing proposed writes,
and preventing external publication without authorization.
