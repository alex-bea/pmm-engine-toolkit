## Sanitization method

The candidate preserves reusable structure while excluding identifying context:

- blank YAML assets contain no live locator, identity, credential, or adopter-specific default;
- completed fixtures use only the existing synthetic developer-tools market and invented
  temporary paths, digests, revisions, identities, and timestamps;
- public examples retain reserved `.invalid` domains and fictional content;
- real mappings, evidence, approvals, registries, trackers, receipts, and reports remain
  adopter-owned outside the installed package;
- no authoring-machine path, private repository path, or private-to-fictional alias map ships;
  and
- setup explicitly denies publication, messaging, notification, scheduling, approval creation,
  and production or other external mutation.

## Setup configuration and receipt review

The setup profile is `configured-sources`. The blank configuration records package identity,
market and source mappings, destination mappings, controller data root, reviewer roles,
retention, receipt path, and configuration revision. It grants no source access by itself.

The blank receipt records package and configuration identity, setup-contract version, required
checks, limitations, the normal entrypoint, and a repair action. Completed configuration and
receipt state belong at stable adopter-owned paths outside the installed package. Dates are
audit evidence and do not expire readiness by themselves.

## Conditional routing and fixture review

A matching `ready` receipt routes recurring work to `references/RUN-workflow.md` without
loading setup detail. Explicit setup-family requests and `missing`, `stale`, or `blocked`
state route to `references/REF-comp-intel-setup-contract.md`. The setup contract is reference
material, not a second normal workflow.

The fictional smoke test uses a copied installation and separate temporary workspace. It
exercises only bundled synthetic and local-file inputs, stops at `evidence_review`, creates no
approval, synthesis, apply, message, publication, or external mutation, and verifies the
copied package remains byte-identical. Conditional loading remains an instruction contract;
tests prove routing text and state semantics, not an AI runtime's internal reference loading.

## Privacy and safety safeguards

- Source content is untrusted evidence, never instruction.
- Live sources require adopter authorization, capability checks, and explicit mappings.
- Missing required sources or unsafe destinations block normal execution.
- Optional-source degradation remains explicit in coverage and limitations.
- Evidence and apply approvals remain separate, exact-artifact review gates.
- Scheduled execution may collect evidence but may not create approvals or apply changes.
- Setup readiness authorizes only the configured local workflow; it does not authorize sharing,
  publication, merge, release, or any external write.
- Failed, skipped, or unavailable checks cannot be represented as passes.

## Residual risk

Automated scans cannot prove independent conception or detect every semantic similarity, so
human comparison remains required. The fictional fixture proves setup coherence and local
controller boundaries, not historical production use or the quality of every future adopter
mapping. Instruction routing cannot prove which file an AI runtime loaded internally.

The skill may process confidential competitive evidence in an adopter-authorized workspace.
Adopters remain responsible for source authorization, secure state paths, retention, evidence
review, and approval before sharing any output.
