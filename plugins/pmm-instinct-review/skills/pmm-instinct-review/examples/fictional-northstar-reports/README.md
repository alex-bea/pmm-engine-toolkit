# Northstar Reports fictional lifecycles

Northstar Reports is a fictional reporting team. Every value under this directory is
synthetic. Any network identifier uses the reserved `.invalid` domain.

## Codex lifecycle (`0.3.1` with legacy compatibility)

The files directly in this directory demonstrate the existing Codex path. The fictional team
learns to lead recurring decision reports with the decision and evidence before chronology.

1. `installation-receipt.json` and `config.json` show disabled installation followed by
   consented enablement with an explicit persisted fictional model. The config also shows one
   exact adopter-owned RUN route and an ordered two-REF choice; the referenced skill files are
   illustrative configuration values, not bundled live targets.
2. `normalized.jsonl`, `audit.md`, `suggestions.md`, and `queue.json` show minimized evidence
   and successful detached extraction.
3. `bucket-summary.md`, `priority-snapshot.json`, and `candidate-card.md` show bucketed,
   breadth-aware review without routing in the first gate.
4. `instinct.md` shows the approved rule; `promotion-preview.json`, `AGENTS-before.md`, and
   `AGENTS-after.md` show the separate exact Codex promotion gate and terminal outcome.
5. `status.json` shows the final read-only state.

These fixtures remain the compatibility baseline. `0.3.1` does not convert or merge them into
Claude state, and its Codex route/model changes do not alter the Claude transaction flow.

## Native Claude lifecycle (`0.3.0` behavior preserved in `0.3.1`)

The independent [`claude/`](claude/README.md) subtree follows a different fictional
preference about release summaries. It covers standalone installation, native lifecycle
hooks, conversation-only evidence, detached Claude extraction, human review, exact
digest-bound approval, background execution, and governed review-only delivery.

The Claude files use `/fictional/...` solely as an inert path namespace. Do not copy those
paths into a real installation. The fixtures represent sequential lifecycle snapshots: for
example, the evidence file is shown for contract review even though a live runtime would
delete it after every candidate in its audit received a decision.

Nothing in either example is evidence about a real person, organization, session, or product.
