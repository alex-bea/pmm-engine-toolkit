# Northstar Reports fictional lifecycle

Northstar Reports is a fictional reporting team. The team wants recurring decision reports
to lead with the decision and evidence before chronology. Every value in this directory is
synthetic; `reports@northstar.invalid` and `https://northstar.invalid/handbook` use the reserved
`.invalid` domain.

## Lifecycle trace

1. `installation-receipt.json` shows an inert Codex install, then explicit local-storage
   consent. `config.json` shows the enabled adopter-owned configuration.
2. `normalized.jsonl` contains only redacted user/assistant text for the final qualifying
   occurrence, `nsr-session-003`. `audit.md` links that evidence to `suggestions.md` and the
   recoverable `queue.json` job.
3. The synthetic store already contains two earlier compatible observations. Their minimized
   text is intentionally not duplicated here; `priority-snapshot.json` lists all three session
   IDs and recomputes the aggregate support, breadth, dates, score, and tier.
4. `bucket-summary.md` presents all three buckets. `candidate-card.md` shows the first human
   gate with no destination or target path.
5. The owner accepts the cluster. `instinct.md` shows the resulting full record after its
   later terminal transition.
6. `promotion-preview.json` shows the second gate for the exact project instruction target.
   `AGENTS-before.md` and `AGENTS-after.md` prove the managed-section insertion is the only
   destination change.
7. `status.json` is the final read-only status: no pending review, no active promotion
   candidate, and one terminal promoted instinct.
